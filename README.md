# Лабораторная работа № 3: множество точек

**Вариант 1 — Point2D, неотсортированное множество.**

`Point2D` хранит целочисленные координаты. `Point2DSet` хранит уникальные точки
в собственном динамическом массиве, сохраняет порядок добавления и удаляет элементы со сдвигом.
Поиск линейный. При заполнении массива вместимость растёт от 0 до 1, затем удваивается.
После удаления вместимость сохраняется.

Тесты и программа используют одну библиотеку `lab03_lib`; `main.cpp` не входит в тесты.

## Возможности

- `add`, `remove`, `contains`, `size`, `empty` и дополнительный геттер `capacity`.
- `operator()` проверяет принадлежность точки.
- `+=` и `-=` добавляют и удаляют одну точку, возвращая ссылку на объект.
- `|`, `&`, `-` создают объединение, пересечение и разность, сохраняя исходные множества.
- `==` и `!=` сравнивают состав множеств независимо от порядка и вместимости.
- `<<` выводит `{}`, `{ (1, 2) }` или `{ (1, 2), (3, 4) }` без перевода строки.

`add` возвращает `false` для дубликата, `remove` — для отсутствующей точки.
Правило пяти реализовано с глубоким копированием и copy-and-swap в копирующем присваивании.
После перемещения источник пуст, его вместимость равна нулю; объект можно использовать снова.
Самоприсваивание и самоперемещение поддерживаются.

Шаблоны, стандартные контейнеры и умные указатели в классах и программе не используются.
Для проверки формата вывода тесты используют `std::ostringstream` и сравнение полученной строки.

## Сборка и запуск

Требуются CMake 3.20+, GNU GCC с поддержкой C++20 и санитайзеров.
На Windows выполняйте команды в Ubuntu WSL из папки проекта:

```bash
cd /home/iszenzi/projects/OOP_labs/OOP_lab_3
cmake -S . -B build/debug -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=g++
cmake --build build/debug
./build/debug/lab03_main
```

Если Google Test установлен, CMake использует его. Иначе скачивает версию `v1.15.2`
в каталог сборки; для первоначального скачивания требуется интернет.
Цели сборки: `lab03_lib`, `lab03_main`, `tests`.
AddressSanitizer и UndefinedBehaviorSanitizer включены для всех целей независимо от конфигурации.
Для проверки Release замените `build/debug` на `build/release`, а `Debug` на `Release`.

## Демонстрационная программа

Условие лабораторной не требует интерактивного меню. Программа запускает готовый пример,
показывающий операции над множествами, принадлежность, обработку дубликата,
копирование и перемещение. Ввод с клавиатуры не требуется.

Основная часть результата:

```text
A = { (0, 0), (1, 2) }
B = { (1, 2), (3, 4) }
A | B = { (0, 0), (1, 2), (3, 4) }
A & B = { (1, 2) }
A - B = { (0, 0) }
```

## Проверки

```bash
ctest --test-dir build/debug --output-on-failure --no-tests=error
```

CMake регистрирует каждый тест Google Test в CTest. Всего 29 тестов: конструкторы,
сравнение и вывод точки, пустое множество, рост массива, дубликаты, удаление,
независимость копий, перемещение и повторное использование источника,
самоприсваивание, обмен, операторы и формат вывода.
Теоретико-множественные операции проверяются на 256 парах подмножеств четырёх точек.
Стресс-тест добавляет 1000 уникальных точек и повторяет добавление для проверки отсутствия дубликатов.

Наборы `PointTest` и `PointSetTest` содержат обычные сценарии.
`PointSetTest_Fail` проверяет ожидаемый отказ операций; эти тесты тоже должны проходить.
CTest включает проверку утечек ASan и останавливает тест при ошибке ASan или UBSan.

Проверка форматирования при установленном clang-format 20:

```bash
clang-format-20 --dry-run --Werror include/lab03/*.hpp src/*.cpp test/*.cpp
```
